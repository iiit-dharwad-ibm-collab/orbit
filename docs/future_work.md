# Future work after the NAACL 2027 Industry submission

The NAACL 2027 Industry Track paper (submitted Oct 31, 2026) leaves these open. They are listed
in order of how much each would strengthen a revision or rebuttal. The paper's Limitations
section and its "protocols for future releases" appendix describe the same gaps.

## 1. Check the judges against human grading

Every open-ended and troubleshooting score comes from an LLM judge (Claude Sonnet). A second
judge (GPT-5.5, `benchmark/second_judge.py`) agrees with it 75.7% of the time on open-ended
answers (kappa 0.53) and 89.6% on troubleshooting answers (kappa 0.70). It is more lenient,
since nearly all disagreements are answers only GPT-5.5 accepts. Neither judge has been
compared with people.

- The expert sheets are ready in `Results/Expansion/ts_threads/human_check/`
  (`items_*.csv`, `judge_*.csv`, `INSTRUCTIONS.txt`), built by `qa/human_check.py prep`.
- Score the returned sheets with `qa/human_check.py analyze`. Report agreement and kappa of
  each judge with the experts, and with the experts among themselves.
- The answer key (`human_check/key/judge_key.csv`) is kept out of git on purpose, because the
  repository is public and the experts must not see the judge's verdicts. It is regenerated by
  `qa/human_check.py prep`.
- The 30-item expert review of the troubleshooting items themselves is also pending.

## 2. Open-book runs and trace-based error analysis

Models never see the evidence an item was built from, so the results measure closed-book
question answering. Run the 2,803 grounded items with their recorded evidence in the prompt and
compare with the closed-book runs. Then use the recorded reasoning traces to say where wrong
answers go wrong. Reviewers will ask for this first, because the evidence and traces are what
set ORBIT apart from OpsEval.

## 3. Frontier and reasoning models

Only five mid-2025 models from one hosting platform were evaluated (Llama 3.3 70B, Llama 4
Maverick, Mistral Medium, Mistral Small, Granite 4.0 H Small). Add at least one frontier model
and one reasoning model. A Claude model can be evaluated only once the troubleshooting items
are no longer written and judged by Claude.

## 4. Shortcut and contamination tests

- **Option-stripping test.** Ask the multiple-choice questions with no options, grade the
  free-text answers with the judge, and compare with multiple-choice accuracy on the same items.
  About 2 to 3 hours of runs, and it needs the Sonnet judge.
- **Ungrounded items.** The options-only baseline (`benchmark/choices_only.py`) is near chance
  overall (30.9% and 32.7%) but solves all 120 items with no source. They stay in the submitted
  evaluation set and are flagged in the paper. Remove or repair them in the public release.
- **Provenance split for free-text formats.** It exists only for multiple-choice items so far.
- **Temporal holdout.** Build items from threads and pages published after every evaluated
  model's training cutoff.
- **Verbatim overlap.** Measure how well rewriting and duplicate removal limit overlap with the
  source threads.
- Add a canary string to released files.

## 5. Data quality before release

- Repair or remove the 367 items excluded for template defects.
- Re-review the 583 items Llama 3.3 70B rewrote after validation.
- Have people check the LLM-assigned reasoning-type and cohort labels.
- The corpus is skewed (62.6% lookups, almost no numerical or temporal reasoning). The
  generated reasoning questions in `Results/Expansion/` are a start on rebalancing it.
- Correct answers lean toward option B (30.8%). Rebalance the option order.

## 6. Statistics and external validity

- Use paired tests, since the same items are scored for every model.
- Run one set of models on ORBIT, OpsEval and OpenRCA.
- Run a study with on-call engineers to show whether rankings predict usefulness on real
  incidents, which is the industry track's main question.

## Where the numbers come from

| Result | Script | Output |
|---|---|---|
| Multiple-choice and open-ended runs | `benchmark/run_benchmark.py` | `benchmark/results/full/`, `chat_mcq/`, `sonnet_judge/` |
| Troubleshooting items and runs | `qa/build_ts_from_threads.py`, `benchmark/rejudge_ts.py` | `Results/Expansion/ts_threads/`, `benchmark/results/ts_threads/` |
| Second judge | `benchmark/second_judge.py` | `benchmark/results/second_judge/` |
| Options-only baseline | `benchmark/choices_only.py` | `benchmark/results/choices_only/` |
| Expert grading sheets | `qa/human_check.py` | `Results/Expansion/ts_threads/human_check/` |

Response caches (`*.db`) and run logs are not committed. The logs record watsonx project IDs,
and the caches can be rebuilt by rerunning.
